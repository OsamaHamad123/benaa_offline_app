# Demo Script - Graduation Presentation

## السيناريو المختصر

الهدف: إثبات أن التطبيق يعمل ميدانيًا بدون إنترنت، ثم يزامن بأمان مع Firebase عند عودة الاتصال.

## 1) Login

- افتح التطبيق.
- سجل الدخول بحساب demo صالح.
- أوضح أن الجلسة تُدار محليًا وأن الوصول محمي.

## 2) Offline Beneficiary Creation

- افصل الإنترنت (Wi-Fi/Mobile data).
- اذهب إلى إضافة مستفيد.
- أدخل البيانات الأساسية واحفظ.
- اعرض أن المستفيد ظهر في القائمة محليًا مباشرة.

## 3) Attachment Upload Pending State

- افتح المستفيد الذي أُنشئ للتو.
- أضف مرفق (صورة أو PDF).
- وضّح أن الحالة أصبحت `pending` لأن الشبكة مقطوعة.
- اذكر أن الملف محفوظ محليًا ولم يُفقد.

## 4) Reconnect Internet

- أعد تشغيل الإنترنت.
- افتح شاشة المزامنة أو انتظر auto-sync.
- اعرض انتقال العناصر من `pending` إلى `synced`.

## 5) Sync to Firebase

- اشرح بسرعة ترتيب المزامنة:
  - رفع ملف المرفق إلى Storage أولًا.
  - ثم حفظ metadata في Firestore.
- بيّن عدم وجود تكرار أو فقدان في البيانات.

## 6) View Synced Data

- افتح شاشة المستفيد مرة أخرى.
- أكد أن حالة السجلات أصبحت synced.
- إذا متاح، اعرض من Firebase Console أن البيانات وصلت.

## 7) Generate Report

- اذهب إلى شاشة التقارير.
- أنشئ تقرير المستفيدين.
- اشرح أن التقرير يشمل البيانات التي أُدخلت أثناء offline بعد المزامنة.

## ملاحظات إلقاء أثناء المناقشة

- جملة دفاع رئيسية:
  - "التطبيق لا يوقف المستخدم عند فقدان الإنترنت؛ يخزن محليًا ثم يحقق مزامنة موثوقة عند عودة الاتصال."
- ركّز على:
  - الأمان (Auth + Rules)
  - الاعتمادية (Retry/Backoff)
  - قابلية التوسع (Backend abstraction)
