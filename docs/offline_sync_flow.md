# Offline Sync Flow

## نظرة عامة

التدفق مصمم بحيث لا يتعطل عمل المستخدم عند انقطاع الشبكة.

## الخطوات

1. المستخدم يُدخل بيانات (مثلاً مستفيد جديد).
2. التطبيق يحفظ البيانات مباشرة في قاعدة محلية Drift.
3. التطبيق يضيف سجلًا في `sync_queue` بالحالة `pending`.
4. عند توفر الإنترنت:
   - SyncManager يقرأ queue حسب الأولوية والجدولة.
   - يرسل كل عملية إلى `RemoteBackend` (Firebase implementation حاليًا).
5. عند نجاح الإرسال:
   - يتم تحديث السجل المحلي إلى `synced`.
   - يتم حفظ روابط السيرفر عند الحاجة (مثل `server_url` للمرفقات).
6. عند الفشل:
   - يتم وضع الحالة `failed`.
   - يتم جدولة retry مع backoff.

## المرفقات تحديدًا

- الصورة/PDF تُحفظ محليًا أولًا.
- أثناء المزامنة:
  - تحقق نوع الملف.
  - تحقق الحجم (<= 10MB).
  - ضغط الصورة عند الحاجة.
  - رفع إلى Firebase Storage.
  - ثم تسجيل metadata في Firestore.

## نقاط دفاع قوية بالمناقشة

- عدم فقدان البيانات عند انقطاع الشبكة.
- التدرج من local consistency إلى eventual consistency.
- الفصل بين منطق المزامنة وواجهة المستخدم.
